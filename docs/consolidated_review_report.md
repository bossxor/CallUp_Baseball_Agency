# CallUp EGM 통합 검토

검토 기준은 콜업 v0.1.10(`f890c91`)의 게임 설계서, 구현 설계서, 로컬 코드와 테스트다. 두 문서를 각각 기능 설계와 구현 설계로 읽었다. 외부 링크는 검토 근거에서 제외했다.

## 판정

첫 플레이 버전 기준은 아직 충족되지 않았다. 시제품에서 국내 10팀 경기, 해외 스카우트, 제한된 협상, 구단 이름 일괄 편집을 검증할 수 있다. 다음 확장에 앞서 등록 실패가 게임 진행을 막는 경로와 저장 복구를 해결해야 한다. 화면 개편은 조작 순서와 클릭 수로 검증한다.

| ID | 우선순위 | 발견과 영향 | 설계에 반영한 조치 | 구현 상태 |
| --- | --- | --- | --- | --- |
| R1 | 차단 | 등록 실패가 예외로 빠지면 같은 주차에서 계속 막힐 수 있다. 뒤 주차 계산 실패는 앞 주차까지 아직 저장하지 못하게 만든다. | 한 주씩 계산하고 저장한다. 미래 등록 실패는 예약 해제, 기존 소속 유지, 무과금 결과로 남기고 다음 주로 진행할 수 있게 한다. | 미구현 |
| R2 | 차단 | 성공 처리한 저장에 쓰기 한도가 없고 읽기는 크기를 제한한다. 파일 저장·가져오기를 Android에서 복구 경로로 검증하지 않았다. | 성공한 파일의 재열기, 실패 시 원본 보존, 다른 설치에서 가져오기, 기존 세이브 마이그레이션을 출시 전에 확인한다. | 미구현 |
| R3 | 주요 | 홈 긴급 안건이 뉴스 카드 뒤로 밀린다. 뒤로 가기에서 원래 목록·선택 위치가 유지되는 기준이 없다. | 홈 상단에서 마감과 응답 행동을 보이고 상세는 직접 연다. 기존 홈·선수·영입의 진입점과 되돌아갈 위치를 검증한다. 작은 화면에서 초기·조용한 주·안건이 겹친 주를 비교한다. | 기준 추가 |
| R4 | 주요 | 현재 시제품과 첫 플레이 목표가 섞여 있다. 해외 구단 목록이 해외 경기 집계처럼 읽힌다. | v0.1.10 기준선을 문서에 적고, 국내 고객·대만 조사부터 실제 Android 흐름과 저장을 확인한 뒤 네 시장으로 확대한다. | 문서 반영 |
| R5 | 주요 | 사건과 만료 정의가 달라 일괄 진행이 멈추는 주를 예측하기 어렵다. | 시작 시 미결 응답 안건과 진행 중 발생한 중단 사건을 구분한다. 마감 주차에 수락할 수 있고 다음 주에 만료한다. 요약·일정·홈에서 사용할 사건 상태를 같은 기준으로 정한다. | 목표 규칙 추가 |
| R6 | 주요 | 기존 구단 갱신과 새 구단 등록의 슬롯·수수료·표시 조건이 섞여 있다. 등록을 마친 선수도 현 코드의 시장 목록은 출신 시장을 기준으로 고른다. | 갱신은 기존 슬롯 유지, 새 등록은 예산과 슬롯 예약을 요구한다. 현재 소속과 출신을 구분하고 등록된 선수의 시장 목록을 검사한다. | 설계 기준 추가 |
| R7 | 주요 | 옛 경기 기록이 새 규칙으로 다시 계산될 수 있다. 추가 국내 경기에는 인천과 무관한 팀에도 추적 선수의 타석 규칙이 적용된다. | 일정 전환 주차를 유지하며, 규칙이 바뀌는 단계에서 완료 경기를 보관하거나 이전 규칙으로 재현한다. 소속에 맞춰 타석을 집계하고, 시즌 간 초기화·이월 대상은 리그 확장 전 확정한다. | 설계 기준 추가 |
| R8 | 주요 | 파견·추가 조사·지원 비용과 얻는 결과가 모호하고, 첫 주 소개를 놓친 뒤의 대체 경로가 드러나지 않는다. | 현재 비용, 자리 수, 정보 차이를 문서화한다. 첫 주 소개와 일반 파견을 구분하고, 지원의 장기 효과는 확정 전까지 목표로 표시한다. | 문서 반영 |
| R9 | 보완 | 선택하지 않은 대안과 검증 명령이 문서에 없었다. | 주·일 단위, 자동·직접 경기, WebView·별도 Android UI의 비용을 작성했다. 단계별 코드 경로와 검증 관문을 추가했다. | 문서 반영 |
