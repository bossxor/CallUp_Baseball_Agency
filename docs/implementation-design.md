# 콜업 구현 설계서

**v0.1 · 첫 플레이 버전**

[구현 기준 저장소: bossxor/CallUp_Baseball_Agency](https://github.com/bossxor/CallUp_Baseball_Agency) · [게임 설계서](game-design.md)

이 저장소를 콜업의 소스 코드와 설계 변경 이력을 관리하는 기준으로 삼는다. 설계 작성 시점에 저장소는 앱 소스가 없는 초기 상태였다. 첫 구현은 TypeScript 기반 시뮬레이션 코어와 모바일 웹 UI를 우선 검토하고, Android 패키징에는 같은 코어를 재사용할 수 있게 둔다. 구현에 착수할 때 저장소의 최신 브랜치와 프로젝트 설정을 다시 확인한다.

## 1. 구현 범위와 구조

첫 목표는 새 게임을 시작해 한국·일본·대만·미국 시장을 조회하고, 선수 계약과 시즌 정산을 거쳐 두 번째 시즌 개막까지 진행하는 것이다. 모바일 화면, 오프라인 싱글플레이와 기기 내 저장을 기준으로 한다.

| 구성 | 담당하는 일 |
| --- | --- |
| **시뮬레이션 코어** | 달력, 경기 결과, 선수 기용과 성장, 리그 순위와 누적 기록, 시즌 전환 |
| **에이전시 업무와 시장** | 스카우트, 고객 계약, 구단 수요, 선수 자격, 제안과 협상, 등록과 회계 |
| **앱 화면** | 사무실, 내 선수, 스카우트, 시장, 협상. 코어가 계산한 결과와 처리할 수 없는 이유를 표시 |
| **저장** | 버전이 있는 로컬 세이브. 시드, 주차, 진행 중인 파견과 협상, 보고함, 계약과 회계를 복구 |

## 2. 주차와 경기

한 저장 파일에는 하나의 달력과 네 시장의 상태가 있다. 주 단위로 진행하되 경기 주차와 시장 등록 기간은 리그 설정에서 관리한다. 주차 처리는 아래 순서를 따른다.

1. 현재 시점의 선수 계약과 로스터를 기준으로 기용을 정하고, 해당 주의 경기를 시뮬레이션한다.
2. 하나의 경기 결과에서 팀 승패와 선수 기록을 함께 집계한다. 팀 순위와 기록 화면은 이 집계를 조회한다. 투구 이닝은 내부적으로 아웃 수로 저장한다.
3. 최근 기록, 부상, 선수층과 가용 자리를 반영해 다음 주 로스터와 구단 영입 수요를 갱신한다. 파견 완료와 협상 답변을 처리하고 정해진 주차에 드래프트나 시즌 변경을 실행한다.
4. 진행 결과와 파생된 보고 메시지를 함께 저장한다. 실행 중에는 주차 버튼의 중복 조작을 막는다. 저장이 실패하면 이전에 저장된 주차부터 재시도할 수 있다.

경기와 이벤트는 저장 파일의 시드와 주차로 재현할 수 있게 한다. 같은 저장에서 같은 행동 순서로 진행한 결과를 재현할 수 있어야 한다.

## 3. 데이터와 계약 규칙

| 데이터 | 필요한 관계와 상태 |
| --- | --- |
| **리그·구단** | 시장, 단계, 달력, 팀 로스터, 포지션별 필요 인원, 등록 가능한 외국인 자리, 가용 예산 |
| **선수** | 현재·잠재 능력, 등록 시장과 소속, 타자·투수 역할, 부상, 선수 선호, 시즌·리그별 경기 기록 |
| **에이전시 계약** | 고객, 기간, 수수료율, 관계, 상담 기록. 선수의 구단 소속과 별도 관리 |
| **구단 계약** | 대상 선수, 구단, 효력 주차, 기간, 보장 금액과 옵션, 보유권과 해외 진출 허가 |
| **제안·회계** | 제안 ID와 시한, 시장과 등록 예정 주차, 예상 역할, 협상 상태. 수수료는 구단 계약 ID를 기준으로 한 번 기록 |

스카우트가 파견되면 지역, 조사 유형과 복귀 주차를 저장한다. 보고서에는 추정 범위를 표시하고, 게임 내부의 실제 잠재력은 별도로 유지한다. 신인 지명 결과는 한국 시장에서만 처리한다. 지명된 선수의 첫 구단 계약은 해당 지명 구단과 협상한다.

구단은 포지션별 필요 인원, 예산과 등록 가능 여부를 평가해 후보에게 제안한다. 자유계약 선수는 등록 조건을 충족하는 구단과 계약할 수 있다. 해외 진출 허가가 있는 소속 선수도 외부 제안을 협상할 수 있으며, 등록 전까지 현재 소속을 유지한다. 마이너에서 메이저로 올라가는 경우에는 동일 미국 구단 조직 내 등록 단계가 바뀐다.

계약 확정은 현재 자격, 제안 시한, 선수 동의, 예산과 등록 자리를 다시 확인한 후 처리한다. 등록이 미래 주차라면 확정 계약과 등록 대기 상태를 저장하고 같은 선수의 다른 제안은 종료한다. 대상 구단의 예산과 등록 자리를 확보한 상태로 효력 주차에 도달하면 기존 소속 종료와 새 소속 등록을 한 번에 반영한다. 수수료는 등록 성공 시 한 번만 기록한다. 검증에 실패하면 소속·예산·회계를 변경하지 않고 사유를 표시한다.

## 4. 구현 순서와 검증 기준

| 순서 | 구현 단위 | 완료 시 확인할 것 |
| --- | --- | --- |
| **1** | 가상 구단과 선수, 네 시장 달력, 주차 진행 | 네 시장의 경기와 순위가 첫 주부터 갱신된다. 같은 경기에서 팀 승패와 선수 기록이 일치한다. |
| **2** | 사무실, 스카우트, 고객 계약, 한국 1·2군과 드래프트 | 국내 2군 선수를 영입한 뒤 콜업 과정을 확인한다. 드래프트 지명 여부에 따라 첫 구단과 협상할 수 있다. 대만 현지 파견이 복귀하면 후보가 보고함에 나타난다. |
| **3** | 구단 수요, 제안 비교, 협상, 등록과 수수료 | 미국 출신 자유계약 선수에게 대만·일본 구단이 제안한다. 선수 동의로 한 곳과 계약하면 다른 제안은 종료되고 수수료는 한 번만 들어온다. 외국인 자리가 가득 찬 구단에는 등록할 수 없다. |
| **4** | 저장·복구, 오프시즌, 시즌 2 개막 | 미결 협상과 파견 상태에서 앱을 닫아도 복구된다. 마감된 제안은 수락할 수 없다. 시즌 2에는 새 시즌 기록이 시작되고 기존 고객 계약과 커리어 기록은 이어진다. |

검증에는 최소한 세 가지 재현 가능한 상황을 준비한다. 국내 2군 고객의 콜업과 연봉 협상, 대만 현지 선수 발굴과 미국 출신 투수의 해외 계약, 등록 대기 상태에서 저장한 뒤 계약 효력과 수수료를 한 번만 적용하는 흐름이다. 시즌 2 개막까지 같은 저장으로 이어가며 누적 기록과 이력이 맞는지 확인한다.
