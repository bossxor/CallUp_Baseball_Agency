## 1. 목적과 “새 게임” 판정

플레이어가 첫 화면·첫 주·선수 카드·기록/경기 화면만 보고도 사인히어(축구 에이전시)로 오인하지 않는다.

목표 문장: **에이전시 게임 → 야구 → 콜업.**

이 로드맵은 그 판정을 단계별로 닫는다. 기존 플레이/구현 설계서는 덮어쓰지 않고 참조한다. 빈 구멍(포크 정체성·야구 시뮬 교체·단계 게이트)만 이 문서가 채운다.

---

## 2. 방식과 순서

**문서 방식:** 마스터 로드맵(본 문서) + 단계 진입 시 상세 스펙. 상세를 지금 한꺼번에 쓰지 않는다.

**구현 순서:**

```text
Roadmap (본 문서) → A 정체성 → B 야구 시뮬 → Residual → Phase UI → C 플레이 기능
```

| 단계 | 한 줄 | 선행 |
| --- | --- | --- |
| **A** | 보이는·들리는 정체성에서 사인히어 제거 | 없음 |
| **B** | 내부 포지션·능력·기록·경기 집계를 야구 규칙으로 | A 완료 |
| **Residual** | 구단·연봉·조항·캘린더 등 축구 잔여 야구화 | B 완료 |
| **UI** | 콜업 전용 다크·앰버 리브랜드 + 홈 피드·세이브1 | Residual 완료. 상세: [phase-ui-design.md](2026-11-24-phase-ui-design.md) |
| **C** | 드래프트·국내 연봉·장기 부상 등 첫 플레이 목표 | **UI 게이트 통과 후** |

**의존성 규칙**

- A 완료 전 B의 내부 코드 ID 치환 금지. (월드 생성 붕괴 이력: `GK`/`DF` 전역 치환)
- B 없이 C의 일부 이벤트 UI는 가능하나, **“새 게임” 판정은 B 필수.**
- **C 착수 전 Phase UI 게이트 통과.** (가독성·형제 게임 티가 남은 채 C 검증 금지)
- 각 단계: 상세 스펙 → `writing-plans` 구현 플랜 → 구현 → 게이트 통과 → 다음 단계 스펙.

## 3. Phase A — 정체성 (범위 / 비범위 / 게이트)

### 3.1 목표

카피·씬·타이틀·아이콘·패키지/Activity의 **사용자 노출**에서 사인히어·축구 잔향을 제거한다. 시뮬 엔진 내부 ID는 건드리지 않는다. 표시 라벨만 야구로 유지·보강한다.

### 3.2 범위 (한다)

1. **브랜드·카피 잔여 소거**  
   UI/셸/약관·프라이버시·메타에 남은 `사인히어` / `SignHere` / `풋볼` / `축구 에이전*` / `Football` 사용자 노출 문자열을 콜업·야구로 치환. `patch-callup.cjs` 안전 모드 확장 + 누락 grep 체크리스트.

2. **타이틀·엠블럼**  
   사인히어 엠블럼·이중 타이틀·스우시 잔여 숨김/교체. 콜업 타이틀이 히어로. 검증: 첫 프레임만으로 축구 에이전시로 안 읽힘.

3. **씬 아트**  
   축구로 즉시 읽히는 에셋부터 교체 또는 CSS/오버레이로 가림. 우선순위: `goal-*`, `shootout-*`, `adshoot-*`, `stadium-*`, `training-*`, `office-*`, `agency-*`, 타이틀 배경. 전량 교체가 한 스프린트에 불가능하면 **노출 빈도 높은 화면**부터. 교체 목록을 A 상세 스펙에 고정.

4. **런처 아이콘·스플래시**  
   `res/drawable` 등 콜업 전용 유지·보강. 사인히어 마크 재등장 금지.

5. **패키지/Activity 사용자 노출**  
   앱 라벨·스토어 전 배지·About/디버그 화면에 `com.signhere`가 **보이지 않게**.  
   smali 클래스 경로 `com.signhere.offline.MainActivity` 전체 rename은 A에서 **선택적**. 기본: Manifest `package=com.callup.agency` 유지, 사용자 노출 0. 전체 smali rename은 A 게이트를 막지 않으면 후속 티켓으로 분리 가능. A 게이트는 **노출 0**이지 경로 rename 완료가 아니다.

6. **폰트·팔레트**  
   금칙 유지: `#141516` + `#C5F23C` + Damion/Bebas 조합 재도입 금지. 밝은 콜업 팔레트(`patch-bright.js` / `callup-theme.css`) 유지.

7. **표시 라벨**  
   포지션·리그·기록 화면의 한국어 라벨이 야구 용어인지 전수. 내부 `GK` 코드는 그대로.

### 3.3 비범위 (A에서 안 한다)

- 엔진 내부 포지션/능력 키 변경, 경기 시뮬 수식 변경
- 드래프트·국내 연봉·장기 부상 신규 로직
- 치트 패널 기능 확장 (유지. 출시 전 제거는 §7)
- TS 원본 앱과 APK 포크 병합

### 3.4 완료 게이트 A

- [ ] 타이틀 → 새 게임 → 홈까지 스크린샷 3장으로 사인히어/축구 에이전시 오인 불가 (제3자 또는 자가 체크리스트)
- [ ] `apk-src` 사용자 대면 자산에서 `사인히어|SignHere|풋볼|Football Agency` grep 결과 0 (주석·치트 개발 라벨·엔진 minify 내부 ID 제외 목록을 A 플랜에 명시)
- [ ] 기기 앱 서랍·최근 앱에 `콜업`만 표시. `com.signhere` 문자열 사용자 UI 0
- [ ] 월드 생성·첫 주 진행이 기존과 동일하게 동작 (회귀)

**A 산출:** 상세 스펙(진입 시) → 구현 플랜 → APK. 본 로드맵의 다음 단계는 B 상세 스펙.

## 4. Phase B — 야구 시뮬 (범위 / 비범위 / 게이트)

### 4.1 목표

내부 포지션·능력·기록·경기 집계가 야구로 읽히고, 저장 데이터에도 축구 스탯 스키마가 남지 않는다. [game-design.md](../../game-design.md)의 타자·투수 기록 용어와 맞춘다.

### 4.2 범위 (한다)

1. **포지션 모델**  
   표시만이 아니라 내부 코드를 야구 포지션(투수 P, 포수 C, 내야 IF, 외야 OF 등 — B 상세 스펙에서 최종 코드표 확정)으로 이전. 월드 생성·스카우트·기용·수요가 같은 표를 씀.

2. **능력치 스키마**  
   `gk`/`sho` 등 축구 키 폐기. 타격·투구·수비 축으로 재매핑. 세이브 마이그레이션 또는 **새 게임 전용**(구 세이브 폐기)을 B 상세에서 하나로 고른다. 기본 권고: APK 포크 시제품은 **새 게임만** (마이그레이션 YAGNI).

3. **경기·기록 집계**  
   팀 승패와 선수 기록을 한 경기에서 함께. 타자: 타석·안타·출루·장타 계열. 투수: 이닝(아웃 수 내부)·삼진·볼넷·자책. [implementation-design.md](../../implementation-design.md) §시뮬레이션 코어와 정합.

4. **UI 바인딩**  
   선수 카드·리그·보고서·주간 요약이 새 스키마만 표시. 축구 용어 잔여 0.

5. **회귀 안전**  
   B는 엔진 `engine-*.js` 패치 또는 교체 전략을 B 상세 스펙에서 고른다. 권고: 최소 패치로 스키마·라벨·집계 훅만 교체. 전면 재작성은 별 프로젝트.

### 4.3 비범위 (B에서 안 한다)

- 플레이어가 경기를 직접 조작하는 모드
- 네 시장 실사 시뮬 동시 고도화 (국내 1·2군 정확도 우선, 해외는 집계 정합 최소)
- C의 드래프트/연봉 이벤트 로직 (스키마만 준비)

### 4.4 완료 게이트 B

- [ ] 신규 세이브에서 선수/리그/보고서 UI에 `GK`/`DF`/`MF`/`FW` 및 축구 스탯 키 노출 0
- [ ] 타자·투수 기록이 game-design 용어로 표시되고, 한 경기 팀 결과와 선수 합이 모순 없음 (스모크 시나리오 문서화)
- [ ] 새 게임 → 4주 진행 → 저장 → 재실행 후 기록 유지
- [ ] A 게이트 회귀 통과

## 6. Phase C — 플레이 기능 (범위 / 비범위 / 게이트)

### 6.1 목표

[game-design.md](../../game-design.md) §첫 플레이 버전 완료 기준을 APK 포크에서 실제로 통과한다. 구현 우선은 [implementation-design.md](../../implementation-design.md) 단계 2→3 순. **선행: Phase UI 게이트.**

### 6.2 범위 (한다)

1. 국내 고객 2군→1군 주간 추적 후 **시즌 후 연봉 협상**
2. 한국 아마추어 **드래프트** 지명 결과 → 첫 구단 계약
3. **장기 부상·부진 지원** 안건 (설계서 선수 지원)
4. 설계서에 이미 있는 해외 제안 비교·대만 스카우트 등과의 **정합 회귀**
5. 중단 조건(드래프트 결과 포함)이 홈에서 멈추는지 검증

### 6.3 비범위 (C에서 안 한다)

- 시즌 2 경제 밸런스 완성
- Play 스토어 출시 패키징 (출시 체크리스트는 §7)
- TS 워크스페이스와 APK 엔진 자동 동기화

### 6.4 완료 게이트 C

- [ ] game-design §첫 플레이 버전 완료 기준 체크리스트 전항 수동 또는 스크립트 통과
- [ ] implementation-design 단계 2·3 검증 표의 APK 해당분 통과
- [ ] A·B·UI 게이트 회귀

**“새 게임” 로드맵 종료 조건:** A∧B∧UI∧C 게이트 모두 통과.
